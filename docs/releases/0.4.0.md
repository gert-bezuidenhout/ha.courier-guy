## Changes

- Adds `pudo_tracking_updated`, emitted only when a parcel's status or latest tracking event changes.
- Supports all existing and future waybills without listing sensor IDs in the automation.
- Includes an example notification automation using `script.notification_all`.
- Avoids notification triggers for unchanged polling, initial setup and restarts. API failures retain the previous successful tracking snapshot.
- Adds regression coverage for initial polling, repeated responses, event changes and recovery.

## Update

Update through HACS and restart Home Assistant. Existing shipments and entity identities remain configured. Dashboard files need no update.

**Disable or replace the previous automation that listens to every `state_changed` event.** Copy [the updated automation](https://github.com/gert-bezuidenhout/ha.courier-guy/blob/0.4.0/docs/examples/pudo-notification-automation.yaml) into the automation editor using **Edit in YAML**. It listens to `pudo_tracking_updated` and requires this integration update.

The example uses the owner's `script.notification_all`; other users should adapt the notification action. Tracking changes while Home Assistant is stopped establish the new baseline on startup and do not send retrospective notifications.
